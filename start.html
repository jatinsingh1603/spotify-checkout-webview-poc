Spotify Android — arbitrary origin in the in-app checkout WebView

This is an ordinary web page on github.io. It is not an app, holds no Android permissions, and has no relationship to Spotify.

Tapping the button below fires a spotify-checkout:// deeplink. The Spotify app will open and render a page of this page author’s choosing inside its own payment UI.

Confirm in the Spotify app

Requires the Spotify Android app installed on this device.

What to look for
  1. Spotify opens — not a browser.
  2. Spotify’s own close button and title bar frame the page.
  3. There is no address bar, so a victim cannot see the real origin.
  4. The loaded page announces that it is attacker-controlled and prints its own github.io origin. A real attacker would instead render a pixel-accurate Spotify login screen.
  5. Spotify’s title bar shows the page’s title — the attacker controls that text too.
The deeplink
spotify-checkout://payment-callback/<uuid>?status=success&success_url=<any URL>

SpotifyCheckoutCallbackActivity is exported="true" with category.BROWSABLE. It URL-decodes success_url and loads it in the checkout WebView with no origin, scheme or allow-list check. Cleartext http:// is accepted as well.
